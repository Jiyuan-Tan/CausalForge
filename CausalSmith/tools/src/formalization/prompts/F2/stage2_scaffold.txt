=== NODE → LEAN MAPPING (one-to-one with the core; one tag per node) ===

Realize each node as its `lean_kind` says and prefix its ONE canonical primary top-level decl with a
LINE comment `-- @node: <core id>` (with the colon; NOT a `/-- … -/` doc comment, which would pollute
the library index's NL field). When one node needs several declarations, tag EXACTLY ONE primary
declaration and leave the companions untagged; reusing an `@node` id is a hard graph-refresh error.
Tag the env S-block's `variable (...)` block with `-- @env: <S-id>`.

- `assumption` → ONE named `def <lean_name> : Prop := <the core condition>`, tagged `-- @node: ass:…`.
  A statement listing it in `hyps` takes it inline `(h : <lean_name> …)`; a class listing it in
  `members` uses it as a field type — the SAME `def` serves both. An `ass:` node is ALWAYS a threaded
  hypothesis: NEVER also emit a `lemma`/`theorem` whose conclusion IS that Prop (discharging it from
  Causalean substrate), even when the plan's `disposition:"reuse"` points at a decl that only
  PARTIALLY fits — that over-formalizes the note and leaves F3 a false `needs-substrate` bridge
  `sorry`. If the reuse decl does not type-match the atom IN FULL, SYNC-BACK the node to
  `lean_kind:"assumption"`/`disposition:"define-local"` and record why.
- `gate:true` statement node → exactly like an `assumption`: ONE tagged `def <lean_name> : Prop :=
  <the core statement conclusion>`, taken inline by consumers. Visible substrate debt — never a
  `lemma`/`theorem … := by sorry`, never an `axiom`, never in the theorem manifest. When
  `gate_class:"cited"`, the `def` must remain **exactly equivalent to the frozen core statement** and
  carry the citation (authors, year, locator, handle) in its docstring. Check the cited source
  separately: if the frozen node states a specialization or one-directional consequence, it is
  enough that the fetched/attested source logically entails that exact consequence under
  specialization premises already explicit in the frozen node. Do NOT require the consequence to imply the whole
  source theorem, broaden its domain to the source's, or import unused source conjuncts; the
  implication must preserve quantifier order, constants, direction, and domain and introduce no
  Lean-only assumption — otherwise leave the frozen encoding unchanged and surface the citation
  mismatch for F2.5. `gate_class:"gated"` (or absent) scaffolds unchanged.
- definition, CLASS (`lean_kind:"structure"`, has `members`) → a `structure` (or typeclass) whose
  fields are the member atoms (each typed by that member's Prop `def`), tagged `-- @node: def:…`. Do
  NOT scatter it into loose hypotheses or emit a per-assumption `a<k>Bundle`; bundling happens only
  at class boundaries the plan names.
- definition, CONSTRUCTION (`lean_kind:"def"`) → a `def` / `noncomputable def` realizing the core
  `construction`, tagged `-- @node: def:…`.
- statement (`lean_kind:"theorem"|"lemma"`) → a `theorem` (T-block) or `lemma`/`private lemma`
  (L-block) named `lean_name`, tagged `-- @node: thm:|lem:|…`, with hypotheses exactly the plan's
  `hyps` (assumption `def`s inline, class structures as bundles). NEVER declare an L-block `theorem`
  (F2.5 flags it); public-vs-private and lemma-vs-theorem are orthogonal.
- open-ended residual (`kind:"openendedquestion"`) → a named tagged `def`, never a theorem and never
  a theorem dependency, by the frozen-node TWO-CASE rule: (A) the node fully specifies every predicate
  needed to state the question → a named never-proved `Prop` encoding exactly those quantified
  regimes, alternatives, and relations; (B) the node explicitly leaves a procedure, sharp-rate
  functional, inference/coverage criterion, lower-bound target, or other truth-condition undefined
  and prescribes a nonassertive carrier → a descriptive NON-`Prop` payload (normally `String`) with
  all stated regimes, alternatives, desiderata, and nonassertion disclaimers and NO witness fields.
  Never replace (B) by `PUnit`/`Unit`/`True`/an empty tag (drops the text) or an invented existential
  `Prop` (fabricates criteria). Exclude both cases from the manifest and from theorem dependencies; a
  genuine resolution lives in a separate `thm:`/`prop:` node.

For a `disposition:"reuse"` node/S-block: `import` the named decl and build on it (do NOT re-state it
over plain ℝ/Set). For `define-local`: write the decl yourself (sorry body for lemmas/theorems; full
body for defs/structures).

=== MISSING-ARCHITECTURE CHECK (escalate before drafting) ===

A `define-local` node is normally build-inline (F2 scaffolds, F3 proves). Return
`blocked-missing-architecture` ONLY when realizing it needs a SUBSTANTIAL new architectural piece,
and only after the MANDATORY PARENT-ABSTRACTION CHECK:
1. Does a parent abstraction fit? A specialized Causalean primitive failing to fit is no grounds to
   escalate if the parent (`POSystem`/`POManski`/`SWIGGraph`/`SCM.Do`) carries the statement —
   scaffold against the parent + theorem-local hypotheses/`let`s.
2. Can the "missing structure" be a proof-internal construction (conditioning, finite indexing,
   assembling existing primitives)? Then it is local construction, not architecture.
3. Is it a single Mathlib-shaped helper? Then a sorry'd lemma in
   `CausalSmith/CausalSmith/Mathlib/<topic>.lean`.
Substantial means: a new `class`/`structure` (forbidden in causalsmith mode regardless); a new core
`def` with its own ≥3-lemma API reused across ≥2 theorems; a whole module of cluster-scale
primitives; or a planned `reuse` decl that does not exist AND no parent carries the statement.
`why_substantial` MUST cite the result of each of the three checks.

=== TAUTOLOGICAL PREDICATE WATCH (Lean-encoding faithfulness — still load-bearing) ===

Do NOT make a node vacuous in Lean:
- `def f := rhs` then `H : f = rhs`; a T-block conclusion `P ↔ body(P)`; a hypothesis that is the
  literal body of an existing `def`; a conclusion that is a re-arrangement of the hypotheses.
- OVER-GENERALIZATION: replacing a constructed core object (a class structure, a construction the
  statement is stated over) with a free variable + defining/existence hypothesis — build the object.
- ASSUMING THE CONCLUSION: `lemma foo (h : P) : P`. Derive from genuine upstream inputs.
- DERIVABLE INTERMEDIATE AS PREMISE: a quantity this block is responsible for deriving is NOT an
  input — derive it, leave the work to `sorry`. Only a STRICTLY-upstream statement's conclusion
  (earlier in `depends_on` order) may be a hypothesis. This INCLUDES a structural PROPERTY of an
  object the block constructs or receives (continuity/convergence, boundedness, a moment or
  algebraic identity) that the note DERIVES from the construction: `have h : … := by sorry`, never a
  premise — even if the property has its own `def`/`@node`; a property the note PROVES is never a
  free "bookkeeping regularity" premise.
- UNIVERSAL-CONSTANT QUANTIFIER ORDER: a constant the note calls universal/absolute is quantified
  OUTERMOST (`∃ c₀, 0 < c₀ ∧ ∀ params …`), never after the parameters (which silently weakens it).
  Mirror the note's dependency structure exactly.
- DROPPED CONSTRAINT IN HELPERS: a predicate constraining an object in the top-level statement is
  threaded down to every helper lemma mentioning that object.
- WEAKENED EXISTENTIAL / DROPPED CONCLUSION: render the quantifier structure and full conclusion at
  the note's STATED strength. Never weaken an existential over a LARGE set (a nonempty open /
  positive-measure / dense subset, a whole admissible family) to a SINGLE witness; never collapse
  "the class of objects for which THERE EXIST parameters realizing the target" into a
  fixed-parameter predicate; never OMIT asserted conjuncts (an identity, a uniqueness/recovery
  clause, a side condition). A logically WEAKER tractable proxy is drift — encode the actual
  structure, or FLAG it (return early with a query) if genuinely not renderable.
Use a SUBSTANTIVE predicate over the substrate's actual primitives. If unsure whether a planned
statement is tautological, FLAG it and return early with a query.

=== UNDER-STRENGTH SIGNATURE WATCH (the opposite failure — unprovable, invisible until F3) ===

- NEVER stub a load-bearing hypothesis as `(_h : True)`; the `sorry` body is the placeholder.
- HYPOTHESIS-COMPLETENESS: when a proof will invoke a named substrate lemma, read its actual signature
  (`lean_local_search` then `lean_hover_info`) and transcribe the hypotheses it REQUIRES
  (measurability/integrability, an independence/cross-fit witness, a positivity bound, an upstream
  conclusion) from the core's named assumptions. Include what the core licenses; invent nothing.
- BOOKKEEPING PREMISES ARE NOT "ASSUMING THE CONCLUSION" — supply them PROACTIVELY (see the
  BOOKKEEPING PREMISE POLICY block). A regularity side-condition a step needs is honest scope on the
  signature; DERIVE a FREE one inline (bounded measurable on a probability measure ⇒ integrable).
  WEAK-OVERLAP CARVE-OUT: integrability of an unbounded inverse-weight/score is NOT free — derive it
  from the tail/overlap assumption.
- MINIMAX / CONVERSE RISK ENCODING (the junk-value trap): a converse over EVERY estimator is FALSE
  when encoded with a real `⨆`/`ciSup` over an unbounded risk set or an ℝ `∫` of a non-integrable
  loss (junk value 0). Encode the witness form `∃ Q ∈ class, rate ≤ risk(Q)`, with an ℝ≥0∞ `∫⁻` of
  the loss or an `Integrable` finite-risk premise scoped inside the estimator binder.
- DISTRIBUTION-CLASS AUXILIARY PINNING: every auxiliary that is a FUNCTIONAL of the law is pinned to
  the law by its defining identity INSIDE the class, never a free `∃`/`∀` parameter (which silently
  widens the class — a prover-safe, silent defect on a converse).
- UNIFORM-CONSTANT MEMBERSHIP ON A CONVERSE: for a uniform-over-class / "constants independent of n"
  conclusion, scaffold witness membership against a FIXED-constant class (constants quantified
  outside n), never the per-law `∃`-constant predicate.
